# 性能优化文档

 Tomato-Brother 的性能现状、已落地优化、待办清单与验证方法。改战斗热路径代码前先读一遍。

> 2026-10-27：P1~P4 待办已全部落地并通过 Windows 打包验证（`BUILD OK`，6 个图集共 87 张贴图）。

## 一、已落地的优化

### 1. 对象池系统（核心，已覆盖所有高频实体）

战斗中每帧大量生成/销毁的实体全部池化，避免 Instantiate/Destroy 的开销和 GC 尖峰：

| 池 | 覆盖对象 | 代码 |
|---|---|---|
| BulletPool | 玩家/敌人子弹 | `Scripts/Pool/BulletPool.cs` |
| EnemyPool | 敌人 | `Scripts/Pool/EnemyPool.cs` |
| GoldPool | 金币掉落 | `Scripts/Pool/GoldPool.cs` |
| HitPool | 受击特效 | `Scripts/Pool/HitPool.cs` |
| BurstPool | 爆炸特效 | `Scripts/Pool/BurstPool.cs` |
| TextPool | 伤害飘字 | `Scripts/Pool/TextPool.cs` |

实现要点：

- 基类 `BasePool<T>` 封装 Unity 官方 `UnityEngine.Pool.ObjectPool<T>`，默认容量 100、上限 500、开启 collection check（重复回收时报错，便于发现问题）
- 子弹回收时移到 `(-40, 0)` 移出视野，代替逐个禁用碰撞体
- 由 `PoolController` 统一挂载管理

**维护红线**：池化对象 `Awake` 只执行一次，重置逻辑必须放 `OnEnable` 或池的 Get/Release 回调；新增强高频实体时先建池，不要直接 Instantiate。

### 2. AudioSource 池（AudioManager）

`Scripts/System/AudioManager.cs` 自建了 AudioSource 池（默认 32 个）：空闲队列 `Queue<AudioSource>` + 播放中列表 + `Dictionary<string, AudioClip>` 音频字典，避免每次播音效动态建 AudioSource、重复查找 AudioClip。

### 3. Sprite Atlas（2026-10-27 已建）

按模块分 6 个图集，全部 `Include in Build`，位于 `Assets/Atlases/`：

| 图集 | 贴图数 |
|---|---|
| Effects.spriteatlas | 4 |
| Enemy.spriteatlas | 10 |
| Map.spriteatlas | 37 |
| Player.spriteatlas | 5 |
| UI.spriteatlas | 4 |
| Weapon.spriteatlas | 27 |

由 `Assets/Editor/AtlasCreator.cs` 自动生成：编辑器菜单 `Tools → Create Sprite Atlases`，或命令行 `-executeMethod AtlasCreator.CreateAtlasesAndBuild`（建图集 + 打包一条龙）。脚本幂等，已存在的图集会跳过；**新增 Sprites 子目录下的贴图后需重新执行**（或手动在图集 Inspector 里补拖）。

### 4. 热路径等待对象缓存（2026-10-27 已改）

- `HurtText.cs`：0.25s 间隔缓存为 `static readonly WaitForSeconds`，消除每次受击的 2 次 GC 分配
- `Burst.cs`：`WaitForSeconds` 按持续时间建立 `Dictionary<float, WaitForSeconds>` 缓存，每次爆炸零分配

### 5. 帧率锁定（2026-10-27 已改）

`Menu.Awake`（Start 场景入口）中设置 `QualitySettings.vSyncCount = 0` + `Application.targetFrameRate = 60`。注意二者必须一起设：vSyncCount 非 0 时 targetFrameRate 不生效。

### 6. 代码层面已规避的反模式

- 组件引用全部在 `Awake`/`Start` 缓存，Update 内无 GetComponent
- 全项目无 `Camera.main` 调用（该 API 有查找开销）
- `FindWithTag` 仅用于 `BaseEnemy.Awake`（池化后只执行一次）和 `Gold` 的懒加载缓存，无每帧查找
- 仅 5 个脚本使用 Update 轮询，其余逻辑协程/事件驱动
- 一次性物体（敌人生成动画、场景 UI）保留 Instantiate/Destroy，频率低，属合理取舍

### 7. Editor 程序集拆分（2026-10-27 已建，开发体验项）

`Assets/Editor/TomatoBrother.Editor.asmdef`（仅 Editor 平台），编辑器脚本与运行时脚本分离编译。

## 二、待办优化清单（可选）

### P1：Physics2D 层碰撞矩阵裁剪

自定义层：6=Wall、7=Player、8=Enemy、9=Weapon。`ProjectSettings → Physics 2D → Layer Collision Matrix` 中关掉永不需要的层对（如 Weapon×Weapon、Enemy×Enemy 若无自伤需求）。**裁剪前必须跑游戏确认弹道/接触判定不受影响**，无法用命令行验证，需人工测试后再动。

### P2：Animator Culling

敌人/特效预制体的 Animator `Culling Mode` 改为 `CullUpdateTransforms`（屏幕外不更新骨骼），需在编辑器里逐预制体设置并目测动画正常。

### P3：`OverlapCircleNonAlloc` 过时 API 替换

编译告警：`BaseWeapon.cs:98`、`LightingShiv.cs:44` 使用了已废弃的 `Physics2D.OverlapCircleNonAlloc`。Unity 6 中 `Physics2D.OverlapCircle` 已使用池化数组、不再产生 GC，可安全替换（顺带消除告警）。

### P4：音频加载策略

当前全部短音效（wav），Decompress on Load 是正确策略，暂无需改。若未来加入长 BGM，将其 `Load Type` 改为 `Streaming` + `Load in Background`。

## 三、如何验证

1. **Profiler**（Window → Analysis → Profiler）：战斗满屏敌人+弹幕时录制 30 秒，关注：
   - CPU: `GarbageCollector.Alloc` 是否有每帧稳定分配（应为 0B 或接近）
   - `BatchCount` / `SetPass` 数（配合图集优化前后对比）
2. **Frame Debugger**：逐 draw call 检查合批情况（图集化后同模块贴图应合并进同一批次）
3. **Memory Profiler**（需另装包）：对比图集化前后纹理内存
4. **冒烟基线**：Fight 场景第 5+ 波（大量敌人）稳定 60 帧视为达标

## 四、明确不做的（以及原因）

- **ECS/DOTS**：项目规模和玩法密度用不到，引入成本远大于收益（见 AGENTS.md）
- **Addressables/AB 热更**：单机学习项目，Resources + 场景内置足够
