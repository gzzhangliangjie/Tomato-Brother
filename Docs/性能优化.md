# 性能优化文档

 Tomato-Brother 的性能现状、已落地优化、待办清单与验证方法。改战斗热路径代码前先读一遍。

## 一、已落地的优化

### 1. 对象池系统（核心，已覆盖所有高频实体）

战斗中每帧大量生成/销毁的实体全部池化，避免 Instantiate/Destroy 的开销和 GC 尖峰：

| 池 | 覆盖对象 | 代码 |
|---|---|---|
| BulletPool | 玩家/敌人子弹 | `Scripts/Pool/BulletPool.cs` |
| EnemyPool | 敌人 | `Scripts/Pool/EnemyPool.cs` |
| GoldPool | 金币掉落 | `Scripts/Pool/GoldPool.cs` |
| HitPool | 受击特效 | `Scripts/Pool/HitPool.cs` |
| BurstPool | 爆炸特效 | `Scripts/Pool/BurstPool.cs` |
| TextPool | 伤害飘字 | `Scripts/Pool/TextPool.cs` |

实现要点：

- 基类 `BasePool<T>` 封装 Unity 官方 `UnityEngine.Pool.ObjectPool<T>`，默认容量 100、上限 500、开启 collection check（重复回收时报错，便于发现问题）
- 子弹回收时移到 `(-40, 0)` 移出视野，代替逐个禁用碰撞体
- 由 `PoolController` 统一挂载管理

**维护红线**：池化对象 `Awake` 只执行一次，重置逻辑必须放 `OnEnable` 或池的 Get/Release 回调；新增强高频实体时先建池，不要直接 Instantiate。

### 2. AudioSource 池（AudioManager）

`Scripts/System/AudioManager.cs` 自建了 AudioSource 池（默认 32 个）：空闲队列 `Queue<AudioSource>` + 播放中列表 + `Dictionary<string, AudioClip>` 音频字典，避免每次播音效动态建 AudioSource、重复查找 AudioClip。

### 3. 代码层面已规避的反模式

- 组件引用全部在 `Awake`/`Start` 缓存，Update 内无 GetComponent
- 全项目无 `Camera.main` 调用（该 API 有查找开销）
- `FindWithTag` 仅用于 `BaseEnemy.Awake`（池化后只执行一次）和 `Gold` 的懒加载缓存，无每帧查找
- 仅 5 个脚本使用 Update 轮询，其余逻辑协程/事件驱动
- 一次性物体（敌人生成动画、场景 UI）保留 Instantiate/Destroy，频率低，属合理取舍

## 二、待办优化清单（按优先级）

### P1：Sprite Atlas（当前最大的缺口）

**现状**：全项目没有任何 `.spriteatlas`，散图各自成图导致 draw call 偏高、内存碎片化。

**做法**：

1. `Assets/Create → 2D → Sprite Atlas`，按模块建集（如 `Enemies`、`Player`、`UI`、`Effects`）
2. 把 `Assets/Sprites`、`Assets/UI` 等目录拖入对应图集的 Objects 列表
3. 勾选 `Include in Build`，Variant 图集可做低清版备用
4. 用 Frame Debugger（Window → Analysis → Frame Debugger）对比合并前后 draw call 数

**注意**：图集对小图收益最大；大背景图单独放，不要强行合入。

### P2：HurtText 的 WaitForSeconds 缓存（热路径 GC）

**现状**：`Scripts/Effect/HurtText.cs:25,27` 每次弹伤害飘字都 `new WaitForSeconds(0.25f)` ×2，每次受击都产生 GC 分配。

**改法**（缓存为静态只读字段）：

```csharp
private static readonly WaitForSeconds HurtInterval = new(0.25f);

// 协程内
yield return HurtInterval;
```

同理可检查 `Burst.cs`（duration 固定时也可缓存）。

### P3：帧率锁定（发版前必做）

**现状**：未设置 `Application.targetFrameRate`。Windows 下受 vsync 控制（QualitySettings 各档 vSyncCount 不一致），移动端会跑满造成发热耗电。

**改法**：在启动场景的入口脚本 `Awake` 中：

```csharp
Application.targetFrameRate = 60;
```

### P4：Assembly Definition（开发体验，非运行时）

**现状**：无 `.asmdef`，所有脚本进 Assembly-CSharp，命令行构建一次脚本编译约 40 秒。

**做法**：至少给 `Assets/Editor` 拆出 `TomatoBrother.Editor.asmdef`（仅引用 UnityEditor），运行时代码后续再拆。

### P5：可选项目

- **Animator 优化**：检查敌人/特效 Animator 的 Culling Mode，改为 `CullUpdateTransforms` 或 `CullCompletely`（屏幕外不更新）
- **Physics2D 层矩阵**：`ProjectSettings → Physics 2D → Layer Collision Matrix`，关掉永不需要碰撞的层对（如飘字层、特效层），减少窄相开销
- **音频加载**：长 BGM 设 `Load in Background` / `Load Type: Streaming`，短音效保持 Decompress on Load + Preload Audio Data

## 三、如何验证

1. **Profiler**（Window → Analysis → Profiler）：战斗满屏敌人+弹幕时录制 30 秒，关注：
   - CPU: `GarbageCollector.Alloc` 是否有每帧稳定分配（应为 0B 或接近）
   - `BatchCount` / `SetPass` 数（配合图集优化前后对比）
2. **Frame Debugger**：逐 draw call 检查合批情况
3. **Memory Profiler**（需另装包）：对比图集化前后纹理内存
4. **冒烟基线**：Fight 场景第 5+ 波（大量敌人）不掉出目标帧率即视为达标

## 四、明确不做的（以及原因）

- **ECS/DOTS**：项目规模和玩法密度用不到，引入成本远大于收益（见 AGENTS.md）
- **Addressables/AB 热更**：单机学习项目，Resources + 场景内置足够
